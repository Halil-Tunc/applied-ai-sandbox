## Feature I picked
- I picked note search: users can type a search term on the homepage and filter notes by title or body text.

## Plan from chat
Feature: Add note search to the sandbox notes app.

Design:
- Add a search form at the top of the homepage with a single text input named `q` and a submit button.
- The form should use the GET method so searches appear in the URL as `/?q=term`.
- In the `home` route, read `q` from `request.args`, trim it, and use it to filter the in-memory `app.notes` list.
- Search should be case-insensitive.
- A note should match if the query appears in either the note title or the note body.
- If `q` is empty or missing, show all notes.
- Pass the current query back to the template so the search box stays populated after searching.
- Show a small message like `No notes found.` if the filtered list is empty.
- Keep the existing in-memory note shape. Do not add a database or new framework.
- Add focused tests for searching by title, searching by body, case-insensitive search, and empty search showing all notes.

Files likely to change:
- `app.py` for reading the query and filtering notes.
- `templates/home.html` for the search form and no-results message.
- A new or existing test file for search behavior.

Edge cases:
- Empty query should behave like no search.
- Search should not crash if a note is missing a field.
- Search should preserve the typed query in the input box.
- Existing note creation tests should still pass.
