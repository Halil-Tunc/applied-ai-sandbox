# M4 — Reading and Verifying Output

## Bug hunt #1 — SQL injection
- Bug: The route builds SQL with an f-string using the user's search query directly, so a malicious user could inject SQL through the `q` parameter.
- Why Claude wrote it: The f-string version looks simple and plausible in a small code sample, especially if Claude focuses on making the query work instead of thinking about unsafe user input.
- Fix: Use a parameterized query instead of string interpolation, such as `db.session.execute(text("SELECT id, title FROM notes WHERE title LIKE :pattern"), {"pattern": f"%{q}%"})`.

## Bug hunt #2 — hallucinated package
- Bug: The code imports `flask_simpleauth`, but that package is not installed and is not the standard Flask authentication library for this use case.
- Why Claude wrote it: Claude likely hallucinated a plausible-sounding package name by combining Flask with authentication concepts instead of checking the actual dependency.
- Fix: Use the real package `Flask-Login`, with imports like `from flask_login import LoginManager, login_required`.

## Bug hunt #3 — edge case
- Bug: `average_rating([])` crashes with a `ZeroDivisionError` because the function divides by `len(ratings)` without checking whether the list is empty.
- Why Claude wrote it: Claude wrote and tested only the happy path with a normal list, so it missed the empty-list edge case.
- Fix: Decide the expected behavior for an empty list, then handle it explicitly, such as returning `0`, returning `None`, or raising a clear `ValueError`.

## Bug hunt #4 — hardcoded secret
- Bug: The API key is hardcoded directly in the source code, which risks exposing a real secret if the file is committed, pushed, logged, or shared.
- Why Claude wrote it: Claude often copies the simplest working pattern from examples, and examples sometimes show placeholder API keys inline even though real projects should not do that.
- Fix: Move the key to an environment variable such as `OPENAI_API_KEY`, read it with `os.environ["OPENAI_API_KEY"]`, keep it out of Git, and rotate/revoke the exposed key immediately if a real key was ever committed or shared.
