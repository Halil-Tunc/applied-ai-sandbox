## Bug hunt #1 — SQL injection
- Bug: The route builds SQL with an f-string using the user's search query directly, so a malicious user could inject SQL through the `q` parameter.
- Why Claude wrote it: The f-string version looks simple and plausible in a small code sample, especially if Claude focuses on making the query work instead of thinking about unsafe user input.
- Fix: Use a parameterized query instead of string interpolation, such as `db.session.execute(text("SELECT id, title FROM notes WHERE title LIKE :pattern"), {"pattern": f"%{q}%"})`.
